# Plan a change

1. Confirm the desired outcome, users, non-goals and accountable human authority.
2. Inspect active product, architecture and accepted decisions selected by context.
3. Compare do-nothing, smaller and requested options when value or feasibility is
   uncertain; recommend one with evidence.
4. Define boundaries, dependencies, controlled signals, acceptance and rollback.
5. Create a work item for bounded-or-higher delivery.
6. Create an ExecPlan only for multi-session, cross-system, migration/refactor,
   multi-phase controlled or parallel work. Follow root `PLANS.md`.
7. Stop at a decision packet if authority, data owner, provider terms or risk
   acceptance is missing.

Return a decision-ready work item, optional ExecPlan and exact next action. Do
not implement during discovery.
